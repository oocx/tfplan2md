# ADR-002: Homebrew Formula Design and Tap Organization

## Status

Proposed

## Context

Feature 089 adds Homebrew installation support for tfplan2md. Homebrew is the standard package manager for macOS and is widely used on Linux (via Linuxbrew/Homebrew on Linux). Users will be able to install tfplan2md with `brew install tfplan2md` after adding the custom tap.

### Requirements

From the Feature Specification:

1. **Custom Tap**: Create `oocx/homebrew-tfplan2md` repository (not submitting to homebrew-core)
2. **Binary-Only Formula**: Download pre-built Native AOT binaries from GitHub Releases (not building from source)
3. **Multi-Platform Support**: macOS x64, macOS ARM64, Linux x64
4. **Checksum Verification**: SHA256 checksums for each platform binary
5. **Automated Updates**: Release workflow updates formula automatically
6. **Testing**: Formula passes `brew audit` and `brew style` validation

### Design Constraints

- **Pre-built binaries available**: Feature 047 provides tar.gz archives for each platform
- **Archive naming convention**: `tfplan2md_<version>_<platform>.tar.gz` (e.g., `tfplan2md_1.2.0_macos-x64.tar.gz`)
- **Single binary per archive**: No subdirectories, just the `tfplan2md` executable
- **Consolidated checksums**: `SHA256SUMS` file generated by release workflow (consolidate-checksums job)
- **No prereleases**: Formula should only be updated for stable releases

## Options Considered

### Option 1: Multi-Platform Formula with Conditional URL/SHA256 (RECOMMENDED)

**Description**: Single formula file with platform detection using `on_macos` and `on_linux` blocks, and architecture detection using `Hardware::CPU.intel?` and `Hardware::CPU.arm?`.

**Formula Structure**:

```ruby
class Tfplan2md < Formula
  desc "Convert Terraform plan JSON files into human-readable Markdown reports"
  homepage "https://github.com/oocx/tfplan2md"
  license "MIT"
  version "{{VERSION}}"

  on_macos do
    if Hardware::CPU.intel?
      url "https://github.com/oocx/tfplan2md/releases/download/v{{VERSION}}/tfplan2md_{{VERSION}}_macos-x64.tar.gz"
      sha256 "{{MACOS_X64_SHA256}}"
    elsif Hardware::CPU.arm?
      url "https://github.com/oocx/tfplan2md/releases/download/v{{VERSION}}/tfplan2md_{{VERSION}}_macos-arm64.tar.gz"
      sha256 "{{MACOS_ARM64_SHA256}}"
    end
  end

  on_linux do
    if Hardware::CPU.intel?
      url "https://github.com/oocx/tfplan2md/releases/download/v{{VERSION}}/tfplan2md_{{VERSION}}_linux-x64.tar.gz"
      sha256 "{{LINUX_X64_SHA256}}"
    end
  end

  def install
    bin.install "tfplan2md"
  end

  test do
    system "#{bin}/tfplan2md", "--version"
    system "#{bin}/tfplan2md", "--help"
  end
end
```

**Template Placeholders**:
- `{{VERSION}}`: Release version (e.g., `1.2.0`)
- `{{MACOS_X64_SHA256}}`: SHA256 for macOS Intel binary
- `{{MACOS_ARM64_SHA256}}`: SHA256 for macOS Apple Silicon binary
- `{{LINUX_X64_SHA256}}`: SHA256 for Linux x64 binary

**Pros**:
- ✅ **Standard pattern**: Follows Homebrew best practices for multi-platform binaries
- ✅ **Single formula file**: Easy to maintain, single source of truth
- ✅ **Automatic platform selection**: Homebrew automatically chooses correct binary
- ✅ **Clear semantics**: `on_macos` and `on_linux` clearly separate platforms
- ✅ **Future-proof**: Easy to add linux-arm64 support later

**Cons**:
- ⚠️ **Multiple checksums**: Requires extracting 3 SHA256 values from `SHA256SUMS`
- ⚠️ **Template complexity**: Update script must replace 4 placeholders

**Trade-offs**: Slight complexity in update script is acceptable for clean formula structure.

---

### Option 2: Separate Formulae per Platform

**Description**: Create `tfplan2md-macos`, `tfplan2md-linux` formulae.

**Pros**:
- ✅ **Simple individual formulae**: Each formula has single URL and SHA256

**Cons**:
- ❌ **Non-standard naming**: Users expect `tfplan2md`, not platform-specific names
- ❌ **Confusing UX**: Users must know their platform to choose correct formula
- ❌ **Maintenance burden**: Multiple formulae to update per release
- ❌ **Against Homebrew conventions**: Standard pattern is platform detection in single formula

**Decision**: Rejected. Does not follow Homebrew conventions.

---

### Option 3: Single Formula with Universal Binary

**Description**: Create a fat binary containing all platforms.

**Cons**:
- ❌ **Not supported by .NET NativeAOT**: Cannot create universal binaries
- ❌ **Massive size**: Would bundle all platforms (~60-90MB)
- ❌ **Complex extraction**: Would need custom install script

**Decision**: Rejected. Not technically feasible with NativeAOT.

---

## Decision

**Implement Option 1: Multi-Platform Formula with Conditional URL/SHA256**

This is the standard Homebrew pattern for distributing pre-built binaries across multiple platforms and architectures.

## Rationale

1. **Follows Homebrew conventions**: The `on_macos` / `on_linux` pattern is documented in the Homebrew Formula Cookbook and used by many popular tools.

2. **Automatic platform detection**: Users don't need to know their architecture. Homebrew detects and selects the correct binary transparently.

3. **Single source of truth**: One formula file (`Formula/tfplan2md.rb`) makes updates and maintenance simpler.

4. **Clean separation**: Platform-specific logic is clearly isolated in conditional blocks.

5. **Extensibility**: Adding linux-arm64 support later is trivial:
   ```ruby
   on_linux do
     if Hardware::CPU.intel?
       url "..."
       sha256 "..."
     elsif Hardware::CPU.arm?
       url "..."
       sha256 "..."
     end
   end
   ```

- **Repository name**: `homebrew-tfplan2md` (Homebrew requires `homebrew-` prefix)
- **Formula file**: `Formula/tfplan2md.rb` (lowercase with underscores if needed)

- **Tap reference**: `oocx/tfplan2md` (used in `brew tap oocx/tfplan2md`)

## Formula Template with Metadata

### Complete Formula File

```ruby
class Tfplan2md < Formula
  desc "Convert Terraform plan JSON files into human-readable Markdown reports"
  homepage "https://github.com/oocx/tfplan2md"
  license "MIT"
  version "{{VERSION}}"

  # macOS platform support
  on_macos do
    if Hardware::CPU.intel?
      url "https://github.com/oocx/tfplan2md/releases/download/v{{VERSION}}/tfplan2md_{{VERSION}}_macos-x64.tar.gz"
      sha256 "{{MACOS_X64_SHA256}}"
    elsif Hardware::CPU.arm?
      url "https://github.com/oocx/tfplan2md/releases/download/v{{VERSION}}/tfplan2md_{{VERSION}}_macos-arm64.tar.gz"
      sha256 "{{MACOS_ARM64_SHA256}}"
    end
  end

  # Linux platform support
  on_linux do
    if Hardware::CPU.intel?
      url "https://github.com/oocx/tfplan2md/releases/download/v{{VERSION}}/tfplan2md_{{VERSION}}_linux-x64.tar.gz"
      sha256 "{{LINUX_X64_SHA256}}"
    end
  end

  def install
    bin.install "tfplan2md"
  end

  test do
    # Smoke test: verify binary runs
    system "#{bin}/tfplan2md", "--version"
    system "#{bin}/tfplan2md", "--help"
  end
end
```

### Metadata Fields Explained

- **`desc`**: Short description (max 80 chars) displayed in `brew info` and `brew search`
- **`homepage`**: Main project URL (GitHub repository)
- **`license`**: SPDX license identifier (MIT matches project license)
- **`version`**: Semantic version number (without 'v' prefix)
- **`url`**: HTTPS download URL for release asset
- **`sha256`**: Checksum for integrity verification (Homebrew validates before installation)

## Binary Archive Requirements

### Archive Contents

Each platform archive (`*.tar.gz`) must contain:
- **Single file**: `tfplan2md` executable (Linux/macOS) 
- **No subdirectories**: Binary at root of archive
- **Executable permissions**: `chmod +x` preserved in tar archive

### Archive Creation

The release workflow already creates compliant archives:

```bash
# From release.yml (lines 296-299)
cd artifacts/${{ matrix.platform }}
tar -czf ../../tfplan2md_${VERSION}_${{ matrix.platform }}.tar.gz ${{ matrix.binary_name }}
```

This creates:
- `tfplan2md_1.2.0_macos-x64.tar.gz` containing `tfplan2md`
- `tfplan2md_1.2.0_macos-arm64.tar.gz` containing `tfplan2md`
- `tfplan2md_1.2.0_linux-x64.tar.gz` containing `tfplan2md`

**No changes required** to existing archive creation process.

## SHA256 Checksum Integration

### Source of Truth

The `consolidate-checksums` job (release.yml lines 357-395) generates `SHA256SUMS` artifact:

```
a1b2c3d4...  tfplan2md_1.2.0_linux-x64.tar.gz
e5f6g7h8...  tfplan2md_1.2.0_macos-arm64.tar.gz
i9j0k1l2...  tfplan2md_1.2.0_macos-x64.tar.gz
m3n4o5p6...  tfplan2md_1.2.0_windows-x64.zip
```

### Extraction Logic

The formula update script will parse this file:

```bash
# Extract SHA256 for each platform
MACOS_X64_SHA=$(grep "macos-x64.tar.gz" checksums/SHA256SUMS | awk '{print $1}')
MACOS_ARM64_SHA=$(grep "macos-arm64.tar.gz" checksums/SHA256SUMS | awk '{print $1}')
LINUX_X64_SHA=$(grep "linux-x64.tar.gz" checksums/SHA256SUMS | awk '{print $1}')

# Validate checksums are non-empty
if [ -z "$MACOS_X64_SHA" ] || [ -z "$MACOS_ARM64_SHA" ] || [ -z "$LINUX_X64_SHA" ]; then
  echo "Error: Missing checksums in SHA256SUMS"
  exit 1
fi

# Validate checksum format (64 hex characters)
if ! echo "$MACOS_X64_SHA" | grep -qE '^[a-f0-9]{64}$'; then
  echo "Error: Invalid checksum format for macos-x64"
  exit 1
fi
```

## Testing Strategy

### Pre-Release Validation

Before releasing a version with Homebrew support:

1. **Syntax Check**:
   ```bash
   brew audit --new-formula tfplan2md
   ```
   Validates Ruby syntax, naming conventions, metadata completeness.

2. **Style Check**:
   ```bash
   brew style tfplan2md
   ```
   Validates Homebrew Ruby style guidelines.

3. **Installation Test (macOS)**:
   ```bash
   brew tap oocx/tfplan2md
   brew install tfplan2md
   tfplan2md --version
   tfplan2md --help
   ```

4. **Functionality Test**:
   ```bash
   # Download a test plan JSON
   curl -LO https://raw.githubusercontent.com/oocx/tfplan2md/main/examples/azure_cdn.json
   tfplan2md azure_cdn.json > output.md
   # Verify output.md is valid markdown
   ```

5. **Uninstall Test**:
   ```bash
   brew uninstall tfplan2md
   which tfplan2md  # Should return nothing
   ```

### Platform-Specific Testing

**macOS x64 (Intel)**:
- Test on macOS 10.15+ Intel machine or GitHub Actions `macos-13` runner
- Verify binary runs natively (no Rosetta translation)

**macOS ARM64 (Apple Silicon)**:
- Test on macOS 11+ Apple Silicon machine or GitHub Actions `macos-14` runner
- Verify binary runs natively (not x64 binary via Rosetta)

**Linux x64**:
- Test on Ubuntu 24.04+ (native or WSL)
- Verify glibc dependency compatibility

### Post-Release Validation

After each release with Homebrew formula update:

1. **Verify formula update**: Check that `Formula/tfplan2md.rb` in tap repository has correct version and checksums
2. **Test installation**: Manually test `brew install tfplan2md` on at least one platform
3. **Verify upgrade path**: Test `brew upgrade tfplan2md` from previous version

## Consequences

### Positive

- ✅ **Standard installation method**: Homebrew is familiar to macOS and Linux developers
- ✅ **Automatic updates**: Users get updates via `brew upgrade`
- ✅ **Transparent platform selection**: Homebrew handles architecture detection
- ✅ **Checksum verification**: Homebrew validates SHA256 before installation
- ✅ **Simple maintenance**: Single formula file, automated updates
- ✅ **Clean uninstallation**: `brew uninstall` removes binary cleanly

### Negative

- ⚠️ **Custom tap required**: Users must run `brew tap oocx/tfplan2md` first (not in homebrew-core)
- ⚠️ **Update latency**: Formula updates happen after release (typically <5 minutes)
- ⚠️ **Platform limitations**: Only macOS and Linux x64 supported initially (linux-arm64 in Phase 2)

### Neutral

- 📝 **Documentation updates**: README.md must include Homebrew installation instructions
- 📝 **Testing effort**: Manual testing on multiple platforms for each release
- 📝 **Tap repository maintenance**: Need to keep tap repository public and accessible

## Implementation Notes

### For Developer Agent

**Tap Repository Setup** (one-time):

1. Create GitHub repository `oocx/homebrew-tfplan2md`
2. Initialize with:
   - `Formula/` directory
   - `README.md` (as specified above)
   - `LICENSE` (MIT, same as main project)
3. Create initial `Formula/tfplan2md.rb` with template placeholders
4. Make repository public

**Formula Update Script** (`scripts/update-homebrew-formula.sh`):

```bash
#!/bin/bash
set -euo pipefail

VERSION="$1"
CHECKSUMS_FILE="$2"
FORMULA_FILE="$3"

# Extract checksums for each platform
MACOS_X64_SHA=$(grep "macos-x64.tar.gz" "$CHECKSUMS_FILE" | awk '{print $1}')
MACOS_ARM64_SHA=$(grep "macos-arm64.tar.gz" "$CHECKSUMS_FILE" | awk '{print $1}')
LINUX_X64_SHA=$(grep "linux-x64.tar.gz" "$CHECKSUMS_FILE" | awk '{print $1}')

# Validate all checksums are present and valid
for sha in "$MACOS_X64_SHA" "$MACOS_ARM64_SHA" "$LINUX_X64_SHA"; do
  if [ -z "$sha" ]; then
    echo "Error: Missing checksum in $CHECKSUMS_FILE"
    exit 1
  fi
  if ! echo "$sha" | grep -qE '^[a-f0-9]{64}$'; then
    echo "Error: Invalid checksum format: $sha"
    exit 1
  fi
done

# Update formula with version and checksums
sed -i "s/{{VERSION}}/$VERSION/g" "$FORMULA_FILE"
sed -i "s/{{MACOS_X64_SHA256}}/$MACOS_X64_SHA/g" "$FORMULA_FILE"
sed -i "s/{{MACOS_ARM64_SHA256}}/$MACOS_ARM64_SHA/g" "$FORMULA_FILE"
sed -i "s/{{LINUX_X64_SHA256}}/$LINUX_X64_SHA/g" "$FORMULA_FILE"

echo "✅ Formula updated to version $VERSION"
echo "   macOS x64: $MACOS_X64_SHA"
echo "   macOS ARM64: $MACOS_ARM64_SHA"
echo "   Linux x64: $LINUX_X64_SHA"
```

Make script executable and commit to main repository:
```bash
chmod +x scripts/update-homebrew-formula.sh
git add scripts/update-homebrew-formula.sh
git commit -m "feat: add Homebrew formula update script"
```
