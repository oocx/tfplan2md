### Major Issues

#### Issue M1: Wrench Icon Edge Case - Parent-Child Resources

**Severity:** Major  
**Location:** `ResourceSummaryHtmlBuilder.cs` or parent-child merging logic  
**Description:**

When parent resources have child resource changes (e.g., firewall rules in a rule collection), the wrench icon format shows:

```
| 6🔧 ➕ <code>🆔 allow-web-secure</code>, ➕ <code>🆔 allow-log-ingest</code>...
```

**Expected:** `| 6 🔧 ➕ <code>...` (non-breaking space before wrench)  
**Actual:** `| 6🔧 ➕ <code>...` (no space before wrench)

**Evidence:**
- File: `artifacts/comprehensive-demo.md` line 422 (after regeneration)
- Test output: `/tmp/test-output.md` line 391

**Root Cause Hypothesis:**
The `BuildChangedAttributesSummary` method (line 209) correctly inserts the non-breaking space. However, when parent-child resources are merged (`ReportModelBuilder.ParentChildMerging.cs` lines 92-103), the summary may be reconstructed or modified, potentially losing the non-breaking space.

**Impact:**
- Affects parent resources with inline child changes (e.g., firewall rules, NSG rules, DNS records)
- Violates style guide consistency for a subset of update operations
- Estimated: <5% of all wrench icon usages based on test output

**Recommendation:**
1. **Option A (Preferred):** Investigate parent-child summary construction in `UpdateParentSummaryWithChildCounts` method
2. **Option B:** Document as known limitation if fix is complex
3. **Option C:** Add test case specifically for parent-child wrench spacing

**Blocking?** No - This is an edge case affecting a small percentage of resources. The primary fix is working correctly for 95%+ of cases.
