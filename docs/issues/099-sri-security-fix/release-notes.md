# Security Fix: Missing Subresource Integrity (SRI) for CDN Resources

This patch fixes a **MEDIUM severity** security vulnerability where HTML templates loaded JavaScript and CSS files from external CDN sources without Subresource Integrity (SRI) checking, potentially exposing users to supply chain attacks.

## 🔒 Security fixes

### Added Subresource Integrity (SRI) protection to all CDN resources

**Problem:** HTML wrapper templates (`github-wrapper.html`, `github-wrapper-light.html`, `azdo-wrapper.html`) loaded external CDN resources (JavaScript and CSS files) without integrity checks. If a CDN was compromised or responded with malicious content, the HTML reports could execute untrusted code in users' browsers.

**Affected resources:**
- GitHub Markdown CSS (dark theme) from cdnjs.cloudflare.com
- GitHub Markdown CSS (light theme) from cdnjs.cloudflare.com  
- Highlight.js CSS (code syntax highlighting) from cdnjs.cloudflare.com
- Highlight.js JavaScript library from cdnjs.cloudflare.com

**Symptom:** CodeQL security scanning flagged CWE-830 warning: "Inclusion of Web Functionality from an Untrusted Source" on all external `<script>` and `<link>` tags in HTML templates.

**Root cause:** The HTML templates used `<script src="https://cdnjs.cloudflare.com/...">` and `<link rel="stylesheet" href="https://cdnjs.cloudflare.com/...">` tags without `integrity` or `crossorigin` attributes. Without SRI, browsers cannot verify that CDN responses match the expected content, leaving the door open for supply chain attacks.

**Fix:** Added Subresource Integrity protection to all 3 HTML wrapper templates:

1. **Added `integrity="sha384-{hash}"` attributes** — Each CDN resource now includes a cryptographic hash (SHA-384) that browsers verify before executing the resource
2. **Added `crossorigin="anonymous"` attributes** — Required for SRI to work with CORS requests to CDN domains
3. **Verified all 6 unique SRI hashes** — Manually validated each hash against actual CDN responses to ensure correctness
4. **Regenerated 18 HTML artifacts** — Updated all example/demo HTML files to use the secured templates

**Templates updated:**
- `src/tools/Oocx.TfPlan2Md.HtmlRenderer/templates/github-wrapper.html` (3 CDN resources protected)
- `src/tools/Oocx.TfPlan2Md.HtmlRenderer/templates/github-wrapper-light.html` (3 CDN resources protected)
- `src/tools/Oocx.TfPlan2Md.HtmlRenderer/templates/azdo-wrapper.html` (2 CDN resources protected)

### Impact on HTML reports

- **Before:** HTML reports loaded CDN resources without integrity checks — vulnerable to supply chain attacks if CDN was compromised
- **After:** Browsers verify cryptographic hashes (SHA-384) before executing CDN resources — malicious content automatically rejected

### Security Impact

**Severity:** MEDIUM — Requires CDN compromise but affects all users viewing HTML reports.

**Attack scenario:**
1. Attacker compromises cdnjs.cloudflare.com or performs a man-in-the-middle attack
2. CDN serves malicious JavaScript (e.g., modified highlight.js with keylogger)
3. User opens HTML report generated by tfplan2md (e.g., `plan.github.html`)
4. Browser loads malicious JavaScript from CDN without integrity check
5. **Result:** Malicious code executes in user's browser with access to report content and session
6. **Impact:** Data exfiltration, session hijacking, or credential theft

**Mitigation:** Users affected by this vulnerability should:
- **Upgrade immediately** to this release — all HTML files generated with the new version include SRI protection
- **Regenerate existing HTML reports** — Old HTML files lack SRI protection; regenerate them using the updated templates
- **Review browser security logs** — Check for any suspicious activity if you've opened HTML reports from untrusted sources

**Note:** This vulnerability only affects HTML output (`--output-format html` or `.html` files). Markdown output (default) is not affected.

## 📚 Related Documentation

### What is Subresource Integrity (SRI)?

Subresource Integrity (SRI) is a security feature that allows browsers to verify that resources loaded from CDNs have not been tampered with. It works by:

1. **Developer provides a cryptographic hash** of the expected resource in the HTML tag
2. **Browser downloads the resource** from the CDN
3. **Browser calculates the hash** of the downloaded content
4. **Browser compares the hashes** — if they match, the resource is executed; if not, it's blocked

**Example:**
```html
<!-- Without SRI (vulnerable) -->
<script src="https://cdn.example.com/lib.js"></script>

<!-- With SRI (protected) -->
<script src="https://cdn.example.com/lib.js" 
        integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/ux..."
        crossorigin="anonymous"></script>
```

### HTML Output in tfplan2md

The `--output-format html` option generates standalone HTML files with embedded Terraform plan content. These files are designed for:
- **Viewing offline** (with fallback CSS when CDN is unavailable)
- **Sharing via email or file attachments**
- **Archiving** in document management systems

To generate HTML output:
```bash
tfplan2md plan.json --output-format html > plan.html
```

**Security best practices:**
- Only open HTML reports from trusted sources
- Regenerate HTML files after upgrading tfplan2md (to include latest security fixes)
- Review browser security warnings before opening HTML files from unknown origins
