### Major Issues

#### Issue M1: Wrench Icon Edge Case - Parent-Child Resources

**Severity:** Major  
**Location:** `ResourceSummaryHtmlBuilder.cs` or parent-child merging logic  
**Description:**

When parent resources have child resource changes (e.g., firewall rules in a rule collection), the wrench icon format shows:

```
| 6🔧 ➕ <code>🆔 allow-web-secure</code>, ➕ <code>🆔 allow-log-ingest</code>...
```

**Expected:** `| 6 🔧 ➕ <code>...` (non-breaking space before wrench)  
**Actual:** `| 6🔧 ➕ <code>...` (no space before wrench)

**Evidence:**
- File: `artifacts/comprehensive-demo.md` line 422 (after regeneration)
- Test output: `/tmp/test-output.md` line 391

**Root Cause Hypothesis:**
The `BuildChangedAttributesSummary` method (line 209) correctly inserts the non-breaking space. However, when parent-child resources are merged (`ReportModelBuilder.ParentChildMerging.cs` lines 92-103), the summary may be reconstructed or modified, potentially losing the non-breaking space.

**Impact:**
- Affects parent resources with inline child changes (e.g., firewall rules, NSG rules, DNS records)
- Violates style guide consistency for a subset of update operations
- Estimated: <5% of all wrench icon usages based on test output

**Recommendation:**
1. **Option A (Preferred):** Investigate parent-child summary construction in `UpdateParentSummaryWithChildCounts` method
2. **Option B:** Document as known limitation if fix is complex
3. **Option C:** Add test case specifically for parent-child wrench spacing

**Blocking?** No - This is an edge case affecting a small percentage of resources. The primary fix is working correctly for 95%+ of cases.

## Critical Questions Answered

### 1. What could make this code fail?

**Answer:**
- **Parent-child edge case** (Issue M1): The wrench icon spacing may not be preserved when parent summaries are reconstructed during child resource merging
- **Non-breaking space encoding**: If the `NonBreakingSpace` constant were changed or the encoding were corrupted, the format would break
- **Template modifications**: If templates bypass `ResourceSummaryHtmlBuilder` and construct summaries manually, they won't benefit from the fix

**Mitigation:**
- The edge case affects <5% of resources and is non-critical
- The `NonBreakingSpace` constant is well-documented and centralized
- Template modifications would be caught by compliance tests

### 2. What edge cases might not be handled?

**Answer:**
- ✅ **Empty names**: Fully handled with Terraform name fallback
- ⚠️ **Parent-child wrench spacing**: One edge case found (Issue M1)
- ✅ **Null values**: Handled via `string.IsNullOrWhiteSpace()` checks
- ✅ **Module resource names**: Extraction logic handles dots correctly

**Overall:** 95%+ coverage, with one documented edge case.

### 3. Are all error paths tested?

**Answer:**
- ✅ **Empty resource names**: `Test_AzApiResourceNames_NotEmpty` validates the fix
- ✅ **Missing attributes**: Null checks prevent crashes
- ❌ **Parent-child edge case**: Not explicitly tested (Suggestion S1)

**Recommendation:** Add test case for parent-child scenarios (Suggestion S1).
