# Issue: Style Guide Compliance Violations in Generated Markdown Reports

## Problem Description

A comprehensive compliance check of 46 generated markdown files (artifacts and examples) reveals that only 19 files (41%) are fully compliant with the style guide documented in `docs/report-style-guide.md`. The remaining 27 files (59%) contain one or more of 6 distinct violation types that cause generated reports to deviate from documented standards.

**Compliance Rate:** 41% (19 of 46 files fully compliant)  
**Total Issues Found:** 6 distinct violation types across 27 files  
**Analysis Source:** `compliance-check-results.md`

## Steps to Reproduce

1. Run the demo artifact generation: `scripts/generate-demo-artifacts.sh`
2. Review generated files in `artifacts/` and `examples/` directories
3. Compare output against style guide requirements in `docs/report-style-guide.md`
4. Observe the 6 violation types detailed below

## Expected Behavior

All generated markdown reports should comply with the style guide requirements:

1. **Changed attribute summaries** should format as: `2 🔧 account_replication_type, tags.cost_center` (with space before wrench icon)
2. **AzAPI resource names** should display friendly names or fall back to Terraform resource names (not empty bold tags)
3. **Tags headers** should include the 🏷️ icon: `**🏷️ Tags:** `key: value``
4. **Module headers** should include the 📦 icon with non-breaking space: `### 📦 Module: root` or `### 📦 Module: `module.network``
5. **Heading hierarchy** should be maintained (no H3 headings inside `<details>` blocks)
6. **Attribute names** in tables should be plain text (not wrapped in backticks)

## Root Cause Analysis

### Affected Components

Based on codebase inspection and violation patterns:

#### Violation 1: Missing Space Before Wrench Icon

**Root Cause:** Summary generation code in changed attribute formatting logic

**Likely Location:**
- File: `src/Oocx.TfPlan2Md/MarkdownGeneration/Helpers/ResourceSummaryHtmlBuilder.cs`
- File: `src/Oocx.TfPlan2Md/MarkdownGeneration/ReportModelBuilder.Summaries.cs`
- File: `src/Oocx.TfPlan2Md/MarkdownGeneration/Summaries/ResourceSummaryBuilder.cs`

**What's Broken:**
The code that formats the changed attribute summary (e.g., `2🔧 account_replication_type`) is concatenating the count directly with the wrench emoji without inserting a non-breaking space between them.

**Why It Happened:**
This was likely overlooked during the initial implementation or during a refactoring of the summary builder logic. The non-breaking space requirement may not have been part of the original specification.

---

#### Violation 2: Empty AzAPI Resource Names

**Root Cause:** AzAPI resource name fallback logic

**Likely Location:**
- File: `src/Oocx.TfPlan2Md/Providers/AzApi/Helpers/ScribanHelpers/AzApi.Rendering.cs`
- File: `src/Oocx.TfPlan2Md/Providers/AzApi/Helpers/ScribanHelpers/AzApi.Rendering.Shared.cs`
- Template: `src/Oocx.TfPlan2Md/Providers/AzApi/Templates/azapi/resource.sbn`

**What's Broken:**
When an AzAPI resource doesn't have a mapped friendly name, the code generates empty `<b></b>` tags instead of falling back to the Terraform resource name.

**Why It Happened:**
The AzAPI resource rendering logic lacks a fallback mechanism. When the friendly name is null or empty, it should use the Terraform resource name (from the resource address) as a fallback, but this logic is missing.

---

#### Violation 3: Tags Without 🏷️ Icon

**Root Cause:** AzAPI template tag rendering

**Likely Location:**
- Template: `src/Oocx.TfPlan2Md/Providers/AzApi/Templates/azapi/resource.sbn`
- File: `src/Oocx.TfPlan2Md/Providers/AzApi/Helpers/ScribanHelpers/AzApi.Rendering.CreateDelete.cs`

**What's Broken:**
The AzAPI-specific tags rendering uses a different format than the standard tags format defined in the style guide. The template likely renders `**Tags:**` without the 🏷️ icon.

**Why It Happened:**
AzAPI provider templates were developed separately from standard AzureRM templates and may not have been updated when the tags format was standardized with the 🏷️ icon in the style guide.

---

#### Violation 4: H3 Headings Inside Details Blocks

**Root Cause:** Obsolete artifact files or test scenarios

**Likely Location:**
- These are **generated output files**, not code issues
- Files: `artifacts/azapi-uat-combined.md`, `artifacts/azapi-nested-grouping-demo.md`, etc.

**What's Broken:**
These files were generated with an older version of the templates that produced H3 headings inside `<details>` blocks, which violates the heading hierarchy requirement.

**Why It Happened:**
These files are not included in `scripts/generate-demo-artifacts.sh`, so they were not regenerated when the templates were fixed. They may be:
- Obsolete test files that should be removed
- UAT artifacts that need a separate generation process
- Edge case scenarios not covered by the main demo generation

---

#### Violation 5: Module Headers Without 📦 Icon

**Root Cause:** Module header generation in main templates

**Likely Location:**
- Template: `src/Oocx.TfPlan2Md/MarkdownGeneration/Templates/default.sbn`
- Template: `src/Oocx.TfPlan2Md/MarkdownGeneration/Templates/summary.sbn`
- File: `src/Oocx.TfPlan2Md/MarkdownGeneration/Helpers/ScribanHelpers/Markdown.cs` (if module headers are generated via helper)

**What's Broken:**
The code or template that generates module headers (e.g., `### Module: root`) does not include the 📦 icon before "Module:" and does not use a non-breaking space after the icon.

**Why It Happened:**
The style guide was recently updated to include the 📦 icon for module headers (lines 168, 180), but the implementation was not updated to match. This is a new requirement that the code doesn't yet implement.

---

#### Violation 6: Attribute Names in Backticks

**Root Cause:** Table generation logic

**Likely Location:**
- Template files that generate attribute tables (could be any of the `*.sbn` templates)
- Possibly: `src/Oocx.TfPlan2Md/MarkdownGeneration/Helpers/ScribanHelpers/SemanticFormatting.*.cs`

**What's Broken:**
One or more templates are wrapping attribute names (table keys) in backticks when they should be plain text according to the "Labels are Text" principle.

**Why It Happened:**
Minor implementation oversight or copy-paste error in a specific template. Since only 1 file is affected, this is likely a localized issue in a specific resource type template.

## Suggested Fix Approach

### Critical: Test-First Development Strategy

**All fixes MUST follow a test-first approach:**

1. **Write tests FIRST** that detect each violation type generically across all generated outputs
2. **Verify tests fail** with current implementation
3. **Implement the fix** in the identified component
4. **Verify tests pass** after the fix
5. **Regenerate demo artifacts** to validate compliance

### Phase 1: Add Generic Style Guide Compliance Tests

Create test files that validate style guide compliance across **all** generated markdown:

**Test File:** `src/tests/Oocx.TfPlan2Md.TUnit/StyleGuideCompliance/StyleGuideComplianceTests.cs`

**Test Methods to Create:**

1. **`Test_ChangedAttributeSummaries_MustHaveSpaceBeforeWrenchIcon()`**
   - Pattern: Regex to detect `\d🔧` (digit directly followed by wrench)
   - Expected: All matches should have pattern `\d\u00A0🔧` (non-breaking space)
   - Run against: All snapshot files, all generated demo artifacts

2. **`Test_AzApiResourceNames_MustNotBeEmpty()`**
   - Pattern: Regex to detect `<b></b>` in summaries
   - Expected: Zero matches
   - Run against: All AzAPI test snapshots

3. **`Test_TagsHeaders_MustIncludeTagIcon()`**
   - Pattern: Regex to detect `\*\*Tags:\*\*` without 🏷️
   - Expected: Zero matches (all should be `**🏷️ Tags:**`)
   - Run against: All snapshot files with tags

4. **`Test_ModuleHeaders_MustIncludePackageIcon()`**
   - Pattern: Regex to detect `^### Module:` without 📦
   - Expected: Zero matches (all should be `### 📦 Module:`)
   - Run against: All snapshot files with modules

5. **`Test_DetailsBlocks_MustNotContainH3Headings()`**
   - Pattern: Multi-line regex to detect `<details>` blocks containing `### `
   - Expected: Zero matches
   - Run against: All snapshot files

6. **`Test_AttributeNames_MustBePlainText()`**
   - Pattern: Regex to detect table rows with keys in backticks (e.g., `| \`[a-z_]+\` |`)
   - Expected: Zero matches in attribute name columns
   - Run against: All snapshot files

**Why This Approach:**

- **Generic detection:** Tests work for ALL resource types, not just specific cases
- **Regression prevention:** New templates must pass style guide compliance
- **Documentation:** Tests serve as executable specification of the style guide
- **Fast feedback:** Developers know immediately if changes violate style guide
