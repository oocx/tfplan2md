# Retrospective: Terraform 1.14/1.15 Plan-JSON Support (Feature 122)

**Date:** 2026-04-30  
**Participants:** Maintainer, Issue Analyst, Requirements Engineer, Architect, Quality Engineer, Task Planner, Developer (two sessions), Technical Writer, Code Reviewer, UAT Tester, Release Manager, Retrospective

---

## Summary

Feature 122 delivered rendering of five previously-silent Terraform 1.14/1.15 plan-JSON fields across three sub-scopes: action invocations (H1), plan-context awareness (H2), and deprecation warnings via the existing Code Analysis pipeline (M2). The implementation spanned two calendar days (2026-04-29 → 2026-04-30), three orchestrator sessions (analysis/planning, core implementation, fixtures/review/release), and produced 147 file changes (6 889 insertions, 333 deletions).

The feature was delivered with high-quality upstream analysis, clean architecture (four focused ADRs, no new flags, no provider-specific renderers), and UAT passed on both GitHub PR #123 and Azure DevOps PR #110.

However, three process issues degraded the workflow:

1. **Developer deferred tasks without Maintainer sign-off** — Tasks 14 (TF 1.13 baseline fixture), 15 (performance guard), and bulk Phase 2/3 fixture coverage were left incomplete; a second Developer session was required to close the gap.
2. **Blocker bug escaped Developer testing** — `CodeAnalysisSectionRenderer.RenderSummary` silently dropped all deprecation warnings when no SARIF findings were present. Four snapshot files were committed under the buggy code and had to be regenerated by the Code Reviewer.
3. **Broken in-flight test file committed** — A commit pushed a test file that caused a build break, requiring an immediate "remove broken file" follow-up commit.

All three issues were found and corrected before UAT, and the final test suite reached 1 327 passing tests.

## What Went Well

### 1. Upstream Analysis Quality
**Evidence:** Issue Analyst work-protocol: "Source diffing of `internal/command/jsonplan/{plan,resource,action_invocations}.go` across `v1.13`, `v1.14`, `v1.15` branches."

The analysis correctly identified every new JSON field, confirmed `format_version` remained `"1.2"` (no breaking change), and proposed a concrete prioritisation. Downstream agents consumed it without re-investigation.

### 2. Architecture Discipline — Four Focused ADRs, Zero New Flags
**Evidence:** Architect: "All decisions respect the maintainer-locked scope (inline action UX, single generic renderer, always-on, hand-crafted fixtures, Stacks out of scope)."

No opt-in flags, no provider-specific renderers, no new top-level section hierarchy beyond what the spec required. `AC-3` (no `*ActionRenderer` outside the generic namespace) was enforced by a NetArchTest rule.

### 3. QE Fixture Inventory Prevented Discovery Work
**Evidence:** QE test-plan.md lists 27 fixtures with IDs F-01..F-60; tasks.md claims specific fixture IDs per task.

The Developer had a complete fixture shopping list and did not need to invent test scenarios mid-session. This is the correct separation of concerns between QE and Developer roles.

### 4. Code Reviewer Caught and Fixed the Blocker
**Evidence:** Code Reviewer work-protocol: root-cause analysis, minimal fix (dual-condition guard), four snapshots regenerated, 1 327 tests passing.

The `RenderSummary` early-return bug would have been a silent functional defect — plans with deprecation warnings but no SARIF scan would have shown "No code analysis findings were reported." The Code Reviewer performed adversarial testing that surfaced this.

### 5. UAT First Pass, Both Platforms
**Evidence:** UAT Tester: "All six test cases passed" on GitHub PR #123 and AzDo PR #110.

Despite the blocker found during Code Review, the post-fix UAT passed on the first attempt with no functional regressions.

### 6. Backwards Compatibility Maintained End-to-End
**Evidence:** Developer: "Defensive ValueKind guards added to `ConfigurationDeprecationReader` after a regression caused by primitive variable values in legacy plan fixtures."

The developer proactively caught and fixed a regression against 1.13-era plans during their own testing before the Code Reviewer saw the code.

## What Didn't Go Well

### 1. Developer Deferred Tasks Without Maintainer Sign-Off
**Evidence:** Developer work-protocol: "Tasks 14 (TF 1.13 baseline fixture), 15 (performance ratio guard), and the bulk of Phase 2/3 hand-crafted JSON fixtures … were **not** completed in this session due to context/time budget."

Tasks.md explicitly requires these (Task 14 owns the H3 rename rebaseline; Task 15 owns the AC-12 performance guard). There is no recorded Maintainer approval for the deferral. This required a second Developer session to close the fixture and snapshot gap, adding a context-switch overhead and leaving Task 15 still incomplete (no performance guard test exists in the final commit).

**Theme:** Boundary / task-completion discipline.

### 2. Blocker Bug Escaped Developer Testing (Silent Feature Failure)
**Evidence:** Code Reviewer: "Blocker bug (fixed): `CodeAnalysisSectionRenderer.RenderSummary` returned early with 'No code analysis findings were reported.' whenever `TotalCount == 0`, even when deprecation warnings were present."

The bug was present in Developer session 1's main implementation commit (`3f7e96ff`). Four snapshot files were generated under the buggy code and committed (`7cfb658f`), meaning the snapshots *asserted* on the wrong output. The Developer had 3 new `ReportModelBuilderDeprecationsTests` tests that cover warning *construction*, but no end-to-end snapshot test for the full deprecation render path at that point — so the test suite passed even with the broken renderer.

**Theme:** Test strategy gap — builder tests passed, renderer integration not exercised until snapshot files were generated.

### 3. Broken In-Flight Test File Committed to Branch
**Evidence:** Git commits `da451737` ("push partial Developer progress") immediately followed by `3f9f68af` ("remove broken in-flight test file to restore green build").

A partially-written test file was committed while the build was broken. This is visible in the PR's commit history and is a hygiene issue — mid-session partial commits should at minimum confirm `dotnet build` succeeds.

**Theme:** Commit hygiene.

### 4. Task 15 (Performance Guard) Remains Incomplete
**Evidence:** Developer work-protocol lists Task 15 as deferred; no commit in the branch adds `ActionInvocationPerformanceTests`. The QE test plan specified a ratio assertion (with-actions median < baseline median × K, K=4). This task appears to have been dropped rather than deferred.

**Theme:** Scope completion.

### 5. Release Manager Screenshot Selector Failure
**Evidence:** Release Manager work-protocol: "Initial screenshot attempt for deprecation warnings failed with selector `.code-analysis-section` (no matching element in rendered HTML)."

The `generate-release-screenshots` skill's default selector did not cover the new Code Analysis section layout introduced by this feature. A manual workaround (`--markdown-file` mode) was required.

**Theme:** Skill/tooling drift from codebase evolution.
